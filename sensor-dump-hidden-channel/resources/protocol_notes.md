# Заметки инженера по формату capture.bin

Дамп получен с диагностического порта промышленного шлюза Modbus во
время калибровки. Формат записей:

```
[type:1 byte][len:1 byte][payload:len bytes][crc8:1 byte]
```

Известные типы записей:
- `0x01` — показание датчика: `payload = [subtype=0x01][float32 big-endian temp]`
- `0x02` — heartbeat: `payload = [subtype=0x02][2 произвольных байта]`
- `0x7F` — диагностический служебный канал, назначение неизвестно
  полевой команде; формат payload: `[seq:1][data...]`.

Файл начинается с 8-байтового магического заголовка `MBDUMP1\x00`,
за которым сразу следуют 4 байта, которые в прошивке шлюза называются
`session_seed` (используется генератором псевдослучайных чисел для
служебного канала диагностики).

Известно, что генератор диагностического канала — стандартный линейный
конгруэнтный генератор (LCG):

```
state[0] = session_seed (32-bit, big-endian)
state[i] = (state[i-1] * 1103515245 + 12345) mod 2^32
keystream_byte[i] = (state[i] >> 16) & 0xFF
```

Байты диагностического канала (`type=0x7F`) — это байты некоторого
скрытого сообщения, зашифрованные побайтовым XOR с этим keystream
(keystream генерируется один раз на весь скрытый канал, по порядку,
независимо от того, как записи `0x7F` перемешаны с другим трафиком в
файле). Поле `seq` в каждой записи `0x7F` указывает порядковый номер
чанка скрытого сообщения (0, 1, 2, ...), а не смещение в keystream.
